## モデル変更の扱い（2026-08-26 決定）

**スキーマのマイグレーション設計（`VersionedSchema` / `SchemaMigrationPlan`）は後回しにする。** モデルの形がまだ動いている段階で V1 を打つと、実験のたびにバージョンを積む必要が出てコストに見合わないため。それまでは「モデルを変えてクラッシュしたら、アプリを削除して再インストール」で運用する。

着手の期限は2つ。どちらも動かせない:

1. **実データを本格的に入れ始めるとき** — 記録が溜まった後にモデルを変えると失われる
2. **CloudKit を入れる直前** — 2台構成になると「入れ直す」で復旧できなくなる（[cloudkit.md](cloudkit.md)）

したがって **モデルを触る機能を先にまとめて片付け、形が固まった時点で V1 を一度だけ打つ**のが最も無駄が少ない。特に「選考履歴」と「志望度の型」の2つが確定すれば、あとは自由に動ける。

### モデルを触る（今のうちにまとめて）

| 項目 | モデルへの影響 |
|---|---|
| 選考の履歴・結果の記録 | `JobEvent` に結果を持たせる。**一番モデルに影響する** |
| 志望度 `Int` → enum 化 | 型変更のため、後からだと `.custom` ステージが必要。**やるなら今** |
| ES の使い回しストック / 面接準備メモ / 添付ファイル | 新モデル追加が中心（既存データへの影響は比較的小さい） |
| リマインダー通知 | 提出物ごとに個別のリマインド日時を持たせるならモデル変更。アプリ全体で「前日20時」固定なら `UserDefaults` で済むのでモデル不要 |

### モデルを触らない（いつやってもいい）

- 企業の削除導線、並び替え、検索対象の拡張
- ダークモード、Dynamic Type、VoiceOver、タップ領域、色の区別
- iPad レイアウト、ハプティクス、String Catalog
- CI / SwiftLint / AppIcon / `project.yml` のタイポ / `@Query` の `#Predicate` 化

> この節は分類の索引であり、個々の項目の進捗は下のリストで管理する。

## 追加機能案

優先度の高い順。着手時にここから個別の設計メモへ切り出す。

- [ ] **締切・予定のリマインダー通知（UNUserNotification）** — 締切管理アプリなのに通知がないのが最大のギャップ。「前日20時」「当日朝」など。`Submission.urgency` の日付更新問題も同時に解決できる
- [ ] **iPhone / iPad 間の同期（CloudKit）** — [cloudkit.md](cloudkit.md) で検討中
- [ ] **選考の履歴・結果の記録** — 現状は企業の「現在のステータス」しか持てず、「いつ何次に通ったか / 落ちたか」が残らない。`JobEvent` に結果（通過 / 落選 / 辞退 / 保留）を持たせ、詳細画面にタイムラインを出す
- [ ] **データのエクスポート / インポート（JSON or CSV）** — 端末紛失で全損する。CloudKit を入れない場合のバックアップ手段としても
- [ ] **ES の使い回し支援** — 「ガクチカ」「志望動機」などの設問ごとに本文をストックし、提出物へ引用できる
- [ ] **面接の準備メモ** — 想定質問リスト、逆質問リストを企業ごとに
- [ ] **カレンダーアプリ連携（EventKit）** — 予定を iOS カレンダーへ書き出し
- [ ] **統計 / 振り返り** — 応募数・通過率・業界別の分布
- [ ] **添付ファイル** — ES の PDF、企業パンフレットなど
- [ ] **ウィジェット / ロック画面** — 次の予定・直近の締切を表示
